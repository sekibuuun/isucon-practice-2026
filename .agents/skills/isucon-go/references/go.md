# Goの改善判断


## ホットパス

テンプレートのparseがホットなら起動時に読み、実行のみをリクエストで行う。動的データまで固定しない。JSON生成・文字列・画像コピーのallocが多ければ不要な生成を減らす。poolや共有bufferは計測根拠がある場合だけ使い、並行利用と返却後参照をレビューする。

外部コマンド生成がホットなら等価なライブラリ処理を検討する。認証・ハッシュ・入力処理の互換性を保ち、チェックを削除して高速化しない。冗長ログを減らす場合も必要なエラー・計測証拠を維持する。

## HTTP

ClientとTransportを再利用し、リクエストcontext・タイムアウトを仕様に合わせる。Response.Bodyはcloseし、再利用したいHTTP/1接続では適切に読み切る。ただし無制限ReadAllで巨大応答をメモリへ載せない。

MaxIdleConnsPerHostはidle接続の保持上限であり、全接続数の上限ではない。MaxConnsPerHost等と区別し、対象Go版と通信先の許可・容量を確認し、値を実測から選ぶ。既存Transportの設定を保持する必要がある場合はClone等を検討する。

## 並行処理・メモリ

goroutine追加が改善とは限らない。DB容量、キュー、ロック待ちを確認する。共有mapは同期し、I/Oを長い全体ロック内へ置かない。goroutineの終了・context伝播・エラー回収を確認する。

raceは並行性の検証、pprofは性能の根拠として用途を分ける。GOMAXPROCSやGC設定は対象CPU割当・メモリ・実測から選び、異なる環境の値を対象環境へ外挿しない。
