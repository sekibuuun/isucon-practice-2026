# キャッシュ改善

単独利用では [ルール](../isucon-workflow/references/regulations.md) と [共通ループ](../isucon-workflow/references/loop.md) を読む。workflowから利用中なら再読込しない。[キャッシュ判断](references/cache.md) は必要な箇所だけ参照する。

- 同じ読み取り・計算の頻度と総コストが処理件数を制限していることを試行ID付きのログ原本で確認する。根拠がなければキャッシュを候補にせず不足する計測を行う。SQL・取得列・重複処理の改善で足りないかも確認する。
- 正本、keyに必要なユーザー・権限・パラメータ、更新・削除・初期化経路、鮮度要件をspecへ書く。
- 許可されたサーバー上のメモリ・KVSを使う。揮発性キャッシュを書き込みデータの唯一の保存先にしない。
- miss、同時生成、更新との競合、初期化後の旧値、複数台、再起動の動作を検証・セルフレビューする。
- 対象環境のcold/warm計測で修正前後の有効スコアとmiss率・生成コスト・メモリを比較し、前後のログ原本の保存先・条件を記録して人間の採否判断を待つ。必要なログが欠けた場合は性能改善を確定せず追加計測する。
