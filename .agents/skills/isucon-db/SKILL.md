# DB改善

単独利用では [ルール](../isucon-workflow/references/regulations.md) と [共通ループ](../isucon-workflow/references/loop.md) を読む。workflowから利用中なら再読込しない。[DB判断](references/database.md) は必要な箇所だけ参照する。

1. MySQL版、schema、SQL呼び出し経路、slow log、DBStats、初期化手順を確認する。試行ID・時間窓付きで判断に使うログ原本と実行計画を保存する。
2. 総時間・回数・走査行数・待ちのログから制限要因となるクエリを選ぶ。COMMITの総時間だけで個別SQLを原因と断定しない。原因を区別できなければ追加計測する。EXPLAINと現実のデータ分布で根拠を確認する。
3. 同じボトルネックの候補から一つ選び、インデックス、N+1のバッチ化、取得列削減、接続再利用などを一つの候補単位で変更する。
4. DDL・設定・初期化互換性はコードにし、確認済みの操作経路で反映する。直接SQLで対象環境の状態だけ変更しない。
5. 結果の件数・順序・NULL・権限・トランザクション・永続性をセルフレビューする。対象環境のベンチで修正前後の有効スコアと同じSQL指標を比較し、前後の原本保存先を記録して人間の採否判断を待つ。ログ欠落時は改善を確定せず追加計測する。
