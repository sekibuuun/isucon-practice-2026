# ISUCONの一ボトルネック改善

最初に [競技ルール](references/regulations.md) と [ループ・記録・レビュー](references/loop.md) を読む。既存の依頼と許可範囲を確認し、ブランチ別記録から現在状態を復元する。

1. 仕様、対象環境、操作経路、スコア計算、当日ルールを確認する。配置・資源・反映・再起動・ベンチ方法を推測しない。
2. 確認済みの対象環境で基準スコアを測り、一つのボトルネックを選ぶ。計測できなければ不足を報告して止める。
3. 改善候補を比較して一つだけ選び、`spec.md` に根拠と比較条件を書く。必要な専門スキルだけを読む。
4. 選んだ候補だけを実装・検証し、セルフレビューでmustを修正する。確認済みの経路で計測用に反映・ベンチし、`run.md` と `review.md` に記録する。
5. 修正前後の有効スコア、SHA、条件、ばらつき、エラーと判断材料を人間へ提示し、採用・却下・再計測の判断を待つ。判断前に正式採用・恒久反映しない。
6. 採用なら正式反映して終了。却下なら候補だけを取り消し復旧を確認して、同じボトルネックの候補選定へ戻る。再計測なら同じ候補を測り直す。別のボトルネックには進まない。

| 観測・作業 | 読むスキル |
|---|---|
| 根拠不足、アクセスログ・OS・プロファイル | [isucon-measure](../isucon-measure/SKILL.md) |
| Go CPU、割り当て、ロック、HTTP、テンプレート | [isucon-go](../isucon-go/SKILL.md) |
| SQL総時間、N+1、実行計画、接続待ち | [isucon-db](../isucon-db/SKILL.md) |
| キャッシュ対象・整合性・重複計算 | [isucon-cache](../isucon-cache/SKILL.md) |
| nginx、OS、構成管理、反映・再起動 | [isucon-infra-ci](../isucon-infra-ci/SKILL.md) |

共通のルールとループは同一作業中に再読込しない。専門資料は必要な箇所だけ読む。必要なコマンド・試行は省かず、大量出力は集計と原本参照で扱う。

競技終了前は正式な操作経路で再起動・データ保持・起動順依存・ベンチ再現を確認する。最良の検証済み状態、未解消must、未検証事項を報告する。

ツールの詳細を確認する場合は [参考サイト](references/sources.md) を参照する。
