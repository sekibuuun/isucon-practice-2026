# ループ・記録・セルフレビュー

## 状態の開始・復元

Gitルートと `git branch --show-current` を調べ、`docs/isucon/<ブランチ名>/` を記録先にする。`/` は階層として保持する。detached HEAD等でブランチ不明なら確認する。パスは引用し、リポジトリ内に収まることを確認する。

既存の3ファイルを読んで更新し、なければ [spec](../assets/spec.md)、[run](../assets/run.md)、[review](../assets/review.md) をコピーして実際の値を記入する。未実行の結果を書かない。共通の反復番号を付け、履歴を保持する。

再開時は記録、HEAD、未コミット差分、反映済みSHA、進行中の反映・ベンチ処理を照合する。最良スコアのSHAと現在SHAを分ける。起動前に環境識別子・SHA・時刻・照合情報を記録し、処理を識別できるIDやコマンドを取得次第追記する。

## 一つのボトルネックと次の行動

一回のワークフローで扱うボトルネックを一つに固定する。候補は複数検討してよいが、同時に実装・計測する性能候補は一つ。不可分な変更は理由と範囲を記録する。must修正は性能候補と区別する。候補が却下された場合だけ、同じボトルネックの候補選定へ戻る。採用後に新しいボトルネックを探さない。

| 観測 | 行動 |
|---|---|
| 根拠不足 | 計測を取得。推測で性能変更を採用しない |
| 検証失敗・未解消must | 修正・検証・再レビュー |
| 反映・ベンチ処理が進行中 | 同じ処理を待機・照合。重複起動しない |
| 処理失敗・中断・timeout | 部分反映状態を確認して原因を修正 |
| 反映成功、ベンチ結果なし | ベンチ処理と結果を確認。スコア有効と断定しない |
| 修正前後の有効結果が揃った | 比較を人間に提示し、採用・却下・再計測の判断を待つ |
| 小さな差・条件不一致・無効ベンチ | 状態を人間に示し、同じ候補の再計測を判断してもらう |
| 採用の判断 | 候補を正式反映し、再起動要件を確認して終了 |
| 却下の判断 | 候補だけ取り消し、同じ経路で復旧・再検証。比較基準が変われば測り直し、同じボトルネックの候補選定へ戻る |

計測用の一時反映と正式採用・恒久反映を区別する。判断待ちの間は候補の追加修正、取り消し、別の改善を進めない。通信断は失敗と断定せず、操作ID・公式ジョブID・対象環境の状態を照合する。新しい根拠なしに同じ失敗を繰り返さない。

## セルフレビュー

実装・検証後、対象環境への反映前に必ずレビューする。差分と関連する読み書き、初期化・再起動、仕様、検証結果を確認する。箇所・再現条件・根拠を具体的に書く。期待と実測を分ける。

- **must**：ルール・仕様・永続性違反、重大な不具合、ベンチ失敗、変更に必要な検証の欠落など、有効スコアの成立・再現を妨げる問題。必ず修正する。
- **should**：計測からスコア向上が見込める性能候補。重要度だけで採用せず、実測で決める。
- **nit**：見た目・好みなどスコアとの関係がない提案。通常見送り、理由を残す。

判断材料は有効なベンチスコアと正当性。mustは有効性の前提として保持する。横ばい・退行でも候補の取り消しは人間の判断後に行う。must修正と性能候補を分けて復旧し、必要な正当性まで戻さない。

修正後は影響範囲を検証・再レビューし、指摘の状態と証拠を更新する。新たな指摘は同じループへ戻す。情報・権限が不足するmustは未解消として報告する。

## 比較・待機・終了

対象環境を操作するときは [実行制御](../../isucon-infra-ci/references/ci.md) を読む。ローカルテスト・microbenchmarkは対象環境の有効スコアを置き換えない。

環境、初期データ、初期化、負荷シナリオ・時間、warm/cold、ログ・プロファイラー設定を揃える。修正前後の有効スコア、SHA、試行数、ばらつき、エラー、原本を並べて記録し、最高値一回だけで優劣を断定しない。差が判別不能なら未確定として提示する。

反映処理の起動だけで完了にしない。待機ツールや短い状態確認を使い、途中経過を伝える。ユーザーの追加指示を制約へ反映する。圧縮・再開後は記録と実際の処理状態を再確認する。

ユーザーの目標、時間・試行予算、競技終了時刻を停止条件にする。採用または継続不能になったら、そのボトルネックの結果を報告して終了する。判断待ちは停止状態であり、承認を推測しない。操作経路が未提供なら勝手に構築せず、許可範囲のコード・記録・ローカル検証まで進めて未検証を報告する。分析だけの依頼では変更・push・外部の反映やベンチ起動をしない。既存の許可範囲を使うが、スキルを新しい権限とみなさない。

人間への提示と最終報告：対象ボトルネック、試した候補、修正前後の有効スコアとSHA・条件・ばらつき・エラー、検証、must・未検証、判断待ちまたは採否、記録参照。競技の完了には再起動・データ保持・起動順・ベンチ再現を確認する。文書作成は文書検証で評価し、対象環境での計測を装わない。
