# 計測・ボトルネック特定

単独利用では [ルール](../isucon-workflow/references/regulations.md) と [共通ループ](../isucon-workflow/references/loop.md) を読む。workflowから利用中なら再読込しない。収集・ベンチ起動は [実行制御](../isucon-infra-ci/references/ci.md) に従う。

1. 対象SHA、環境識別子・割当資源、サービス・DB・負荷生成の配置、初期化、ベンチ条件、ログ・プロファイル設定をrunに記録する。確認済みの対象環境で基準値を取得する。
2. 有効スコア・エラー・レイテンシ・処理件数と、同時間帯のCPU・メモリ・ディスク・ネットワークを照合する。練習では負荷生成側も観測する。本番ベンチへのログインはしない。
3. アクセスログはメソッド・URI群別の総時間、回数、平均・最大・分位点を見る。IDは適切に集約し、異なる処理を混ぜない。平均だけ・遅い一件だけで優先順位を決めない。
4. 全体を切り分けてからDBやGoを深掘りする。CPU飽和、I/O待ち、ロック、接続プール待ち、負荷生成不足を区別する。
5. 今回扱う一つのボトルネックについて候補、観測根拠、期待効果、比較条件をspecへ書く。候補は一つずつ実装・計測する。

詳しい道具の使い方は [計測手順](references/measurement.md)。原本は既存の非公開な保存先から参照し、記録に秘密・全ログを貼らない。
