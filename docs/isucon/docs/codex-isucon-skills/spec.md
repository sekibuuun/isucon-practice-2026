# 設計メモ

## 現行の目的・制約

- ブランチ：`fix/codex-isucon-skills`（既存記録は `docs/codex-isucon-skills` で開始）。
- 目的：Go向けの役割別ISUCONスキルを作り、agent loop、ブランチ別記録、セルフレビュー、スコアによる修正判断を実現する。
- 許可範囲：このブランチへのスキル・資料実装と検証。ユーザーの追加指示により `.agents/skills` もGit管理・コミット対象にする。
- 範囲外：実行環境の構築・設定反映、自動化経路の作成、本番ベンチ起動、GitHub公開範囲の変更、push。
- ルール：ISUCON2026公式 https://isucon.net/archives/59966826.html （2026-10-04確認）。当日マニュアル・ポータル情報は未提供。
- 対象環境：将来の性能計測では環境の種類を限定せず、確認済みの対象環境と操作経路を使用する。本作業は文書検証で完了を判定する。
- 公開範囲：ユーザー指定は非公開・チーム限定。実際のGitHub設定は未確認であり、変更・pushしない。

## 反復 001：設計

- 6スキルを `.agents/skills` に作成し、workflowにルール・共通ループ・書籍要約・参考サイト・3種テンプレートをまとめる。
- 各専門スキルは単独利用でもルールと共通ループを読む。必要な詳細だけを読み込む。
- 記録は `docs/isucon/<ブランチ名>/spec.md`、`run.md`、`review.md`。ブランチのスラッシュは階層として保持。
- mustは有効スコアの前提、性能候補は期待根拠と対象環境での実測で採否を決める。
- CIは環境排他、SHA/run照合、中断再開、部分反映・復旧まで扱う。
- 根拠：指定PDFの関連本文・章まとめ・付録、公式ルール、Codex記事、ツール公式サイト。抽出全文は保存・登録しない。
- 受け入れ条件：Markdown・相対リンク・メタデータの読み直し、Git差分検査、机上ケースでのループ判断、セルフレビュー後の修正・再確認。
- 最新のユーザー指示：スキル記載だけでよく、Python実行や検証用パッケージ追加は行わない。標準validatorの実行は完了条件から外す。
- 追加の編集指示：スキルMarkdownの出典・背景説明を削除し、実行手順と判断基準に絞る。技術の参照リンクは参考サイト資料へ集約する。
- 文書作成のため基準スコア・性能測定は対象外。未計測の改善値を記録しない。

## 反復 003：実行環境非依存化

- 環境をAWS、VM等の名前で分岐せず、サービス・DB・負荷生成の配置、割当資源、環境識別子、操作経路からなる環境プロファイルとして扱う。
- 接続・反映・初期化・再起動・ベンチ・成果物回収は、リポジトリまたはユーザーが示した既存手順を使う。ローカルコマンド、SSH、管理ツール、CIを選択肢とし、存在しない方式を仮定しない。
- 永続的な変更はコードで管理する。対象環境への直接操作を一律禁止せず、許可済みの操作経路として記録・照合する。
- TerraformとGitHub Actionsは既存構成にある場合だけ使う方式固有資料として残す。本番は当日マニュアルと公式ベンチマーカーを優先する。
- 受け入れ条件：固定された環境前提が残っていないこと、相対リンク・メタデータ・Markdown差分が正しいこと、複数の環境・操作経路を机上確認できること。
