# セルフレビュー

## 反復 001：文書・運用の整合性

| シナリオ | 確認結果 |
|---|---|
| 初回調査 | 有効ベンチを基本に複数候補を4列・優先順で提示し終了する |
| 候補指定で改善 | 調査ID・候補IDを参照し、現SHA・環境・条件と原因を検証する |
| 対象未指定・一覧なし | 選択待ち、またはsurveyを案内。自動選定しない |
| 原因の見立て違い | 原因を訂正し、対象除外には根拠を要求。別対象に自動着手しない |
| スコア横ばい | 有効結果・ばらつきを提示し、人間の採否・再計測判断を待つ |
| 採用 | 正式反映後の根拠で一覧更新。採用だけで解消扱いしない |
| 却下 | 復旧確認後に更新。却下実装の結果で現在状態の順位を書き換えない |
| 全候補対応・再調査 | ユーザー依頼で同じ調査IDを再利用。候補なしでも無理に生成しない |
| 計測不足・経路なし | 不足を記録し、計測基盤の新規構築や原因の断定をしない |

- 共通のブランチ記録とsurvey専用記録の適用範囲を明記し、専門資料のrun記録指示をsurvey.mdへ読み替えることを明記。
- 仕様・永続性・再起動、must修正、一候補ずつの比較、人間の採否判断は維持。
- 未解消must：なし。実環境の挙動・性能は未検証であり、本変更の評価対象外。
- 実エージェントによる競技環境の操作試験は行っていない。上記は文書の机上確認。
