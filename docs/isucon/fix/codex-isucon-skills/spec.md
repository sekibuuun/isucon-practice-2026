# 設計メモ

## 現行の目的・制約

- 対象：ブランチ `fix/codex-isucon-skills`、基点 `fc25931ff92a4de8c122f87f1ad2bfa1486bc13d`。
- 目的：6つのISUCONスキルで試行ごとのログ原本保存を必須にし、ログが原因を区別できない場合は性能変更でなく追加計測を選ぶ。
- ユーザー指定：ベンチ起動直前に、実際のnginxアクセスログであることを確認した上で `sudo truncate -s 0 /var/log/nginx/access.log` を行う。
- 許可範囲：スキルと利用資料の修正。過去問アプリ、対象環境、ベンチは操作しない。

## 反復 001：設計

- 根拠：ISUCON14練習記録では通知APIの大量アクセスとDBの多数のCOMMITが観測されたが、アクセスログに応答時間がなく、処理件数の制限要因は特定できなかった。終了時の空席数も負荷中の推移を示さない。
- 変更範囲：6スキルの入口、workflow・measure・infra-ciの詳細資料、workflowの3テンプレート。
- 受け入れ条件：試行ID・SHA・条件・時間窓・原本保存先・欠落・判断を追えること。ベンチ前の前試行ログ保存、指定コマンドによるtruncate、ベンチ後の当該試行ログ保存が順序付きで記載されること。
- 性能評価：文書変更のため対象環境のベンチは行わない。

## 反復 002：developとの統合

- `develop` の一ボトルネック・一候補ずつ・人間の採否判断待ちを、反復001のログ原本保存と追加計測条件に統合する。
- ログから制限要因を区別できる場合だけ一つのボトルネックを選ぶ。修正前後の有効スコアと同じ指標を提示し、判断前に正式採用・取り消し・別候補の実装をしない。
- 採用後は終了、却下後は復旧して同じボトルネックの候補選定へ戻る。対象環境の操作は行わない。
